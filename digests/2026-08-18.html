Summary

pallet-revive’s ReviveApi version 2 was merged in polkadot-sdk, adding versioned runtime API functions with payload enums and version_declarations() reporting supported versions. ParaSpell also launched ParaSpell CLI for XCM starter projects while setting XCM Visualizer to wind down by end-2026.

Report

Technical

  • pallet-revive now has a versioned runtime API interface as part of ReviveApi version 2: each versioned function uses paired input/output payload enums, and version_declarations() reports the maximum supported payload version per function at the queried block. The implementation is merged in polkadot-sdk; networks receive it when they ship a runtime containing the changes, while unversioned functions remain available but are deprecated. (via Polkadot Forum Article - 0xOmarA)
  • New validator-nomination research suggested nominators may not need to fill all 16 nomination slots: under the current 600-seat / 724-candidate model, 4 active nominations reportedly provide a 99.8245% chance of at least one active validator (via rossbulat, rossbulat).

Ecosystem

  • ParaSpell introduced ParaSpell CLI, a wizard for generating XCM starter projects across XCM SDK or XCM API, React, Vue, or Node.js, and PAPI, Polkadot.js, or Dedot clients, with optional Swap, EVM, and Snowbridge extensions; it replaces the now-deprecated SDK and API starter templates. ParaSpell is also winding down XCM Visualizer, which stays online until the end of 2026, and all three repositories remain public and open source. (via Polkadot Forum Article - dudo50)
